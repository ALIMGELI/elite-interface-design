# Research and Inspiration Protocol

## Purpose
Use public examples to learn principles and patterns, then create an original interface suited to the current product.

## Suggested public reference sources
- Official product pages, design engineering articles, and public documentation.
- Public case studies published by product design agencies.
- Design systems and accessibility documentation.
- Public interface showcases, used as visual references rather than unquestioned authority.

Possible subjects to study include Linear, Stripe, Vercel, Apple, Figma, Framer, Ramotion, Clay, Qubstudio, and Neuron. These are examples of companies or studios, not a claim that all share one style or that every showcased pattern is appropriate.

## Research procedure
1. Prefer primary sources and official case studies where available.
2. Record the URL, date accessed, product area, and the specific design principle observed.
3. Separate observed facts from interpretation.
4. Do not claim a company uses a pattern unless the source supports it.
5. Do not copy logos, brand assets, proprietary illustrations, or a distinctive screen layout one-to-one.
6. Translate observations into a design decision for the current product.
7. If web access is unavailable, work from general design knowledge and clearly avoid pretending that current references were researched.

## Useful analysis questions
- What is the visual hierarchy?
- How is navigation organized?
- How does the interface handle dense information?
- Which colors have semantic meaning?
- What interaction feedback is provided?
- How does the design adapt to small screens?
- What can be learned without reproducing the original?
